# PoemsSite

Одностраничное приложение с автопоиском русской поэзии: полнотекстовый поиск PostgreSQL,
опциональный Elasticsearch и опциональный поиск по смыслу на PostgreSQL + pgvector.

## Описание

Данное приложение представляет собой одностраничный сайт на ASP.NET Core с одним текстовым полем, реализующий механизм
автопоиска при наборе текста. Результаты отображаются в виде выпадающего списка.
Семантический режим использует локальную многоязычную модель `intfloat/multilingual-e5-small`.

## Технологии

- ASP.NET Core
- Entity Framework Core
- PostgreSQL
- Docker
- Elasticsearch (опциональный)
- pgvector и ONNX Runtime (опциональный семантический поиск)

## Запуск приложения с использованием Docker Compose

### Предварительные требования

- Docker и Docker Compose
- Python 3.9+ для скачивания набора данных

### Пошаговая инструкция

1. **Получите исходный код.**
   Клонируйте репозиторий:
   ```bash
   git clone https://github.com/V0R0N01D/PoemsSite.git
   cd ./PoemsSite/compose
   ```

2. **Скачайте набор данных одной командой.**
   ```bash
   python download.py
   ```
   На Linux/macOS при необходимости используйте `python3` вместо `python`.
   Скрипт скачивает [Russian Poetry Dataset](https://www.kaggle.com/datasets/greencools/russianpoetry)
   и сохраняет только `russianPoetryWithTheme.csv` в `compose/init-data`.

3. **Запустите приложение.**
    - Запуск по умолчанию (со скачиванием образов с Docker Hub):
      ```bash
      docker compose up -d
      ```

    - Локальная сборка:
      ```bash
      docker compose -f compose.yaml -f compose.local.yaml up -d --build
      ```
      Нужен весь репозиторий. .NET SDK и Python для сервиса модели устанавливаются в образах.
      Локальный файл подключается вторым, поверх основного. Благодаря `pull_policy: build`
      приложения пересобираются и без явного `--build`, с использованием кеша Docker.
    - Для запуска версии с Elasticsearch (требует больше оперативной памяти):
        1. Измените параметр `ELASTICSEARCH_ENABLED` на `true` в файле `.env`
        2. Выполните команду:
           ```bash
            docker compose --profile elastic up -d
            ```
            Для локальной сборки:
            ```bash
            docker compose -f compose.yaml -f compose.local.yaml --profile elastic up -d --build
            ```
    - Для запуска версии с поиском по смыслу:
        1. Измените параметр `VECTOR_SEARCH_ENABLED` на `true` в файле `.env`
        2. Выполните команду:
           ```bash
           docker compose --profile vector up -d
           ```
           Для локальной сборки:
           ```bash
           docker compose -f compose.yaml -f compose.local.yaml --profile vector up -d --build
           ```

    - Для запуска версии с Elasticsearch и поиском по смыслу:
        1. Измените параметры `ELASTICSEARCH_ENABLED` и `VECTOR_SEARCH_ENABLED` на `true` в файле `.env`
        2. Выполните команду:
           ```bash
           docker compose --profile "*" up -d
           ```
           Для локальной сборки:
           ```bash
           docker compose -f compose.yaml -f compose.local.yaml --profile "*" up -d --build
           ```

    - Для остановки:
      ```bash
      docker compose --profile "*" down
      ```
    - Для остановки с удалением данных:
      ```bash
      docker compose --profile "*" down -v
      ```

4. **Доступ к приложению.**
   После запуска приложение будет доступно по адресу: [http://localhost:32164](http://localhost:32164)
   (порт настраивается через `SITE_PORT`).

Сервис `embeddings` использует ONNX Runtime CPU и INT8-веса E5-small (около 118 МБ),
один процесс и ограниченную очередь вычислений. GPU и API-ключи не нужны.
Веса и токенизатор скачиваются с Hugging Face при первом запуске в volume `embedding-models`.

### Как устроена индексация

- Используется закреплённая ревизия модели и токенизатора
  `614241f622f53c4eeff9890bdc4f31cfecc418b3` и файл `onnx/model_qint8_avx512_vnni.onnx`.
  ONNX Runtime выбирает доступные инструкции CPU; производительность зависит от процессора.
- Загрузчик после импорта CSV читает стихи из PostgreSQL небольшими порциями и передаёт модели.
  Модель объединяет строфы примерно в 400 токенов, предпочитает границы строф и строк,
  оставляет около 48 токенов перекрытия. Очень длинные строки разделяются по токенам.
- К каждому фрагменту добавляются `passage: `, автор и название (метаданные ограничены 64 токенами).
  Полный вход повторно проверяется на предел 512 токенов. Конец длинного стихотворения не отбрасывается.
  Для запроса используется `query: ` и отдельный предел 256 токенов. Превышение возвращает HTTP 400.
- В `poem_chunks` сохраняются текст, номер фрагмента, ссылка на стихотворение и нормализованный
  `vector(384)`. Поиск использует косинусное расстояние и HNSW-индекс.
- Из 300 ближайших фрагментов выбирается до 30 уникальных произведений. Рейтинг произведения —
  близость его лучшего фрагмента (`1 - cosine distance`). Это приблизительный поиск; рейтинг не является
  вероятностью. При множестве фрагментов одного произведения выдача может содержать менее 30 стихов.
- Время семантического поиска в интерфейсе включает расчёт эмбеддинга и запрос к PostgreSQL.
  Отмена HTTP-запроса передаётся из сайта дальше; уже начатое CPU-вычисление модели заканчивается.
  Сервис кеширует эмбеддинги последних 128 запросов в памяти.
